# HSE Book Catalog

Сквозной проект по дисциплине «Инфраструктура и администрирование».

Сервис позволяет вести каталог книг: просматривать список, получать книгу по идентификатору, добавлять новые книги и искать их по автору.

## Возможности

- Просмотр списка книг
- Получение книги по идентификатору
- Добавление новых книг
- Поиск по полному имени автора или его части без учета регистра
- Ограничение количества книг через переменную окружения
- Проверка доступности и версии приложения
- Автоматические тесты и проверка проекта в GitHub Actions

## Технологии

- Python 3.11 — используется в GitHub Actions
- FastAPI
- Uvicorn

## Установка и запуск

Требуются Python 3.11 и Git. Команды ниже предназначены для macOS и Linux.

1. Клонируйте репозиторий и перейдите в папку проекта:

```bash
git clone https://github.com/rdejov-code/hse_book_catalog.git
cd hse_book_catalog
```

2. Создайте и активируйте виртуальное окружение:

```bash
python3 -m venv .venv
source .venv/bin/activate
```

В Windows PowerShell используйте:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
```

3. Установите зависимости:

```bash
python -m pip install -r requirements.txt
```

4. Из корня проекта с активным виртуальным окружением запустите приложение:

```bash
python -m uvicorn app_final:app
```

## Проверка работы

Приложение доступно по адресу:

- http://127.0.0.1:8000/ — приветственное сообщение

Интерактивная документация:

- http://127.0.0.1:8000/docs

После запуска доступны:

- http://127.0.0.1:8000/health — ожидается `{"status": "ok"}`
- http://127.0.0.1:8000/version — ожидается `{"version": "1.0.0"}`
- http://127.0.0.1:8000/books — список книг

## Маршруты

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | `/` | Приветственное сообщение |
| GET | `/health` | Проверка доступности приложения |
| GET | `/version` | Версия приложения |
| GET | `/books` | Список всех книг |
| GET | `/books/{book_id}` | Получение книги по идентификатору |
| POST | `/books` | Добавление книги |
| GET | `/books/search/by-author` | Поиск книг по автору |

## Добавление книги

1. Откройте `/docs`.
2. Выберите `POST /books`.
3. Нажмите `Try it out`.
4. Заполните тело запроса:

```json
{
  "title": "Три товарища",
  "author": "Ремарк"
}
```

5. Нажмите `Execute`.

Требования к данным:

- `title` — обязательная строка с названием книги.
- `author` — обязательная строка с именем автора.

Ограничений на длину строк и запрета на пустые строки в текущей реализации нет.

При успехе сервер возвращает код `200` и добавленную книгу. Для исходного каталога ответ будет таким:

```json
{
  "id": 3,
  "title": "Три товарища",
  "author": "Ремарк"
}
```

Идентификатор назначается приложением: максимальный существующий `id` увеличивается на единицу.

Если количество книг достигло `MAX_BOOKS`, сервер возвращает код `400`:

```json
{
  "detail": "Достигнут лимит книг"
}
```

## Получение книги

В `/docs` выберите `GET /books/{book_id}`, нажмите `Try it out`, введите идентификатор и нажмите `Execute`.

При успехе возвращается код `200` и объект книги. Например, запрос `/books/1` вернет:

```json
{
  "id": 1,
  "title": "Время жить и Время умирать",
  "author": "Ремарк"
}
```

Если книги с указанным идентификатором нет, возвращается код `404`:

```json
{
  "detail": "Книга не найдена"
}
```

## Поиск по автору

В `/docs` выберите `GET /books/search/by-author`, нажмите `Try it out`, заполните обязательный параметр `author` и нажмите `Execute`.

Поиск проверяет вхождение введенной строки в имя автора без учета регистра. Например, `рем` найдет книги автора «Ремарк».

Для исходного каталога результат будет таким:

```json
{
  "count": 1,
  "items": [
    {
      "id": 1,
      "title": "Время жить и Время умирать",
      "author": "Ремарк"
    }
  ]
}
```

Если совпадений нет, сервер возвращает код `200` и `{"count": 0, "items": []}`.

## Проверка работоспособности

После запуска откройте:

```text
http://127.0.0.1:8000/health
```

Ожидаемый код ответа — `200`, тело ответа: `{"status": "ok"}`.

Версию можно получить по адресу:

```text
http://127.0.0.1:8000/version
```

Ожидаемый ответ для текущей версии: `{"version": "1.0.0"}`.

Проверка из другого терминала:

```bash
curl -i http://127.0.0.1:8000/health
curl -i http://127.0.0.1:8000/version
curl -i http://127.0.0.1:8000/books
```

## Настройки окружения

| Переменная | Назначение | Значение по умолчанию |
| --- | --- | --- |
| `MAX_BOOKS` | Максимальное количество книг в каталоге | `100` |

Лимит включает две начальные книги. Значение считывается при загрузке приложения и должно быть целым числом.

Пример запуска с другим лимитом в macOS и Linux:

```bash
MAX_BOOKS=50 python -m uvicorn app_final:app
```

В Windows PowerShell:

```powershell
$env:MAX_BOOKS = "50"
python -m uvicorn app_final:app
```

В репозитории есть `.env.example` с примером настройки:

```dotenv
MAX_BOOKS=100
```

Сам по себе файл `.env` не загружается приложением автоматически. Переменную можно задать в терминале, как показано выше.

Версия `1.0.0` задана константой `APP_VERSION` в `app_final.py`. Переменная окружения `APP_VERSION` в текущей реализации не используется.

## Тестирование

1. Из корня проекта с активным виртуальным окружением установите зависимости для тестирования:

```bash
python -m pip install -r requirements-dev.txt
```

2. Запустите тесты:

```bash
python -m pytest -v
```

Четыре теста проверяют:

- Ответ `/health`
- Получение списка книг
- Получение существующей книги по идентификатору
- Ответ `404` при запросе отсутствующей книги

## Логи и диагностика

Логи выводятся в терминал с запущенным Uvicorn.

Uvicorn показывает входящие запросы, HTTP-коды ответов и ошибки обработки. Приложение дополнительно сообщает о запуске, запросах списка книг, добавлении книг, поиске по автору и запросах отсутствующих книг.

Примеры текста сообщений приложения:

```text
Сервис запущен. Версия=1.0.0, MAX_BOOKS=100
Запрос списка книг, всего=2
Добавлена книга id=3 title=Три товарища
Поиск по автору=Ремарк
Книга id=9999 не найдена
```

### Сервис не открывается

- Проверьте, что команда запуска продолжает работать и в терминале появилось сообщение `Application startup complete`.
- Убедитесь, что адрес `http://127.0.0.1:8000` открывается на том же компьютере, где запущен сервис.

### Ошибка No module named ...

- Проверьте, что активно виртуальное окружение и установлены зависимости.
- Запускайте приложение из папки, содержащей `app_final.py`.

### Порт уже занят

Остановите предыдущий экземпляр приложения или используйте другой порт:

```bash
python -m uvicorn app_final:app --port 8001
```

В этом случае адрес сервиса — `http://127.0.0.1:8001`.

### Ответ 400

При добавлении книги достигнут лимит `MAX_BOOKS`. Проверьте количество книг через `GET /books`. Чтобы увеличить лимит, перезапустите приложение с другим значением переменной окружения; при этом каталог вернется к двум начальным книгам.

### Ответ 404

Проверьте путь запроса. При запросе книги по идентификатору убедитесь, что она существует: получите актуальный список через `GET /books`.

### Ответ 422

Запрос не прошел проверку данных. Проверьте обязательные поля `title` и `author`, их типы, целочисленный идентификатор книги или наличие параметра `author` при поиске.

### Ответ 500

Посмотрите traceback в терминале сервера. Последняя строка содержит тип и описание ошибки.

### Добавленные книги исчезли

Каталог хранится в памяти процесса и сбрасывается после перезапуска приложения. Это относится и к автоматическому перезапуску при использовании `--reload`.

### Ошибка при настройке MAX_BOOKS

Если приложение не запускается с ошибкой преобразования в целое число, проверьте значение `MAX_BOOKS`. Например, используйте `100`, а не текстовую строку.

## GitHub Actions

Файл `.github/workflows/ci.yml` запускает проверку при `push` и `pull_request`.

Выполняются следующие шаги:

1. Получение кода репозитория.
2. Настройка Python 3.11 на Ubuntu.
3. Установка зависимостей из `requirements-dev.txt`.
4. Запуск `python -m pytest -v`.
5. После успешного выполнения — сохранение артефакта `app-files`.

Артефакт `app-files` содержит `app_final.py`, `requirements.txt` и `README.md`.

Результаты проверки доступны во вкладке **Actions** репозитория. Архив находится в разделе **Artifacts** соответствующего запуска.
